Critical lesson review / 25 October 2026

Useful introduction; stronger evidence of learning needed

The sequence gives learners a coherent route from basic ideas to an AI project. The exercises are accessible and the newer agents lesson makes tool calls concrete. My main challenge is that completion currently shows that someone explored the activities and recognised explanations, not that they can independently judge an AI system.

Highlighted editsLesson reviewOpen lessons

What I corrected

  • Misleading certainty: a tiny classifier's probability estimate, temperature as a truth control, scripted RAG outcomes and guarantees about local processing.
  • Examples that contradicted their own teaching: unsupported survey conclusions, agent drafts with invented event details and partial credit for ignoring an approval rule.
  • Implementation mismatches: routed messages still shown as model input, arbitrary free-text predictions, send-tool argument mismatch and a promise that quiz results were saved.

Lesson 08 has been removed from the course for now. Its source is archived outside the served website. There are seven active lessons, ending with Evaluation & Safety.

What I would challenge next

  1. Test judgement with plausible alternatives. Many quiz distractors are obviously wrong. Use two reasonable answers that differ in evidence, assumptions or safeguards, and require a reason.
  2. Separate trying an activity from mastering it. Several activities count as done after a click or reveal. Keep exploration progress, but add a short applied task assessed against a rubric before claiming competence.
  3. Measure with examples the learner has not tuned against. Repeat attempts help learning, but use different held-out scenarios for assessment.
  4. Teach failure analysis throughout. Ask where a failure arose: source quality, retrieval, prompt, generation, tool permissions or evaluation. Give learners ambiguous and incomplete cases.

These are curriculum recommendations, not claims that the larger assessment redesign has been implemented.

Evidence checked

The following primary sources informed the technical corrections; the teaching recommendations above are my assessment.

  • scikit-learn: naive Bayes cautions that naive Bayes probability estimates should not be taken at face value.
  • Transformers generation documentation defines temperature as a change to token probabilities. It does not certify factual accuracy.
  • Elastic text analysis documentation describes stemming and synonym handling in keyword search.
  • FAISS documentation describes a similarity-search library.
  • Anthropic: Building effective agents distinguishes fixed workflows from model-directed agents and recommends starting with simple designs.
  • Ollama FAQ distinguishes local and cloud processing and explains how to disable cloud features.
  • ICO introduction to anonymisation defines anonymous information in terms of whether people remain identifiable, including when combined with other information.
