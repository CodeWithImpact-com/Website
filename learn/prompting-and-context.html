Prompting and context: why the same AI gives different answers.

A model only knows what it learned in training and what you put in front of it. Learn how to write clear instructions, give useful context, and understand why outputs vary.

  • About 20 minutes
  • Beginner friendly
  • No account required
  • Original diagrams

A prompt is a brief, not a magic spell

Think of a language model as a capable new volunteer on their first day. They know a lot in general, but nothing about your charity, your data or your audience unless you tell them. A good prompt is simply a good brief.

Everything the model can “see” at once, including your instructions, pasted documents and the conversation so far, is called the context. It has a size limit, called the context window. And even with the same context, settings like temperature change how predictable the answer is.

    Key ideas to take away
    
          
      
            
    • Be specific about the task, audience and format. “Three bullet points for trustees” beats “summarise this”.
      • 
            
    • Give the model the facts. Without your data in the context, it may guess, ask for the missing data or decline to answer. Check that the response uses the evidence you supplied.
      • 
            
    • Tell it what to do when unsure. Ask it to say “not in the data”, then test whether it follows that instruction. A prompt cannot guarantee that it will.
      • 
            
    • Temperature changes variety, not truth. Lower settings concentrate the next-token probabilities. They can still produce the same wrong answer repeatedly, so verify factual claims at any setting.
      • 
            
    • Context windows are finite. In long conversations, early instructions can drop out of view. Restate what matters, or start a fresh conversation.
      •

    Messages, roles and system prompts
    
              
    Chat models receive a list of messages, each with a role. The system message sets standing instructions, and an application can preserve it while trimming older conversation turns. This lab demonstrates one simple trimming policy; it does not model how every chat application handles context.
    

    messages = [
  {"role": "system", "content": "You summarise survey data for charity trustees. "
                                "Only use the data provided. If something is not in the data, say so."},
  {"role": "user",   "content": "Survey data:\n" + survey_text + "\n\nWrite three bullet points."},
]
    
              
    Sampling settings
    
              
      
                
    • Temperature rescales scores before softmax: P(i) ∝ exp(z_i / T).
      • 
                
    • Top-p (nucleus sampling) only samples from the smallest set of tokens whose probabilities add up to p.
      • 
                
    • Greedy decoding always picks the top token. This gives consistent results, but the wording can be repetitive.
      • 
              
    
              
    Techniques worth knowing
    
              
    
                
    Few-shot prompting
    Including worked examples of the input and desired output in the prompt.
    
                
    Prompt chaining
    Splitting a task into steps, each with its own prompt, passing outputs forward (Gullí, Chapter 1).
    
                
    Structured output
    Asking for JSON or a fixed template so results can be checked automatically.
    
                
    Context engineering
    Deciding what information goes into the context, in what order, and what stays out. You will use this approach in RAG (Lesson 05).
