PUT THE SIX LESSONS TOGETHER

Make a prediction.
Make a useful decision.

A fictional community kitchen needs tomorrow's meal plan. Use the lesson experiments to gather evidence, then write a short project note that another person can question and use.

This worksheet joins the existing course. Work through it as you finish each lesson; the optional notebook puts the same workflow into Python.

Choose a sensible decision rule before looking at scores.

For this exercise, prefer a model only if it reduces validation MAE by at least 2 meals against the baseline. Ask separately whether its underestimates are acceptable: MAE alone gives shortages and surplus equal weight. This threshold is a teaching choice, not evidence about a real kitchen. Passing it does not establish a reliable improvement; that needs more time-aware assessment and a decision with the people using the service.

  1. Frame the question and identify information available before the decision.
  2. Inspect the data, protect later days, and fit preparation on training rows.
  3. Use the regression and model comparison experiments to explain the evidence you would need.
  4. Record what remains uncertain. A synthetic-data exercise is practice, not a model ready to deploy.

Experiments use small lesson-specific synthetic datasets. The notebook independently generates 180 fictional days; its scores will differ. Label the source of each result you record.

YOUR PROJECT NOTE

Six decisions worth writing down.

Your answers stay in this open page. They are not submitted or saved by this worksheet. Download your note before leaving or refreshing. Avoid entering personal information.

01 / THE DECISION

Start with the person using it.

Who plans the meals? At what time? What action follows? How do shortages and leftovers affect people?

02 / THE EVIDENCE

Make the inputs earn their place.

List the target and inputs available at prediction time. Describe missing values, unusual days, weekday coverage and any leakage you excluded.

03 / THE SPLIT

Practise the future honestly.

For future-day prediction, keep chronological order. The notebook uses the first 108 days for training, next 36 for validation and last 36 for the final test. Learn imputation, scaling and categories from training rows only.

04 / THE COMPARISON

Beat something simple.

The notebook predicts the training median as its baseline. Set your useful improvement and error-cost checks before selection. Compare every candidate on the same validation days.

05 / THE RESULT

Report what happened.

Name your dataset or experiment. Record validation scores, variability and selection reason. Report the locked final-test result only after choosing. A small advantage may need more evidence.

06 / THE LIMITS

Leave a plan for mistakes.

Mention synthetic data, changes over time, uncertainty and affected groups. Set a review trigger, a fallback and a person responsible. A prediction does not decide the right meal buffer for you.

OPTIONAL PYTHON

Run the whole workflow.

An original notebook generates 180 fictional days, inspects only the training block, fits preprocessing inside pipelines, compares a median baseline, Ridge and a small random forest, then opens the final test once.

It exports the fitted pipeline and a model note. You need Python, Jupyter and the listed packages; the notebook runs on your computer, not on this page.

Tested on 26 October 2026 with Python 3.13, NumPy 2.5, pandas 3.0 and scikit-learn 1.9: it runs from start to finish. Outputs are left empty so you see the results yourself.

What happens when you run it. Ridge regression is chosen on validation (6.5 meals average error, against 12.2 for the median baseline). On the final test it does worse: 9.0 meals, and it underestimates 72% of days. That gap is the point: a model chosen on one period can drift on later days, which is why the notebook ends with a monitoring plan.
